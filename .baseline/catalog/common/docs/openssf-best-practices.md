# OpenSSF Best Practices

This repository is prepared for the [OpenSSF Best Practices Badge](https://openssf.org/projects/best-practices-badge/). Its project entry is [{{OPENSSF_PROJECT}}]({{OPENSSF_PROJECT}}). The badge is earned through project self-certification at [bestpractices.dev](https://www.bestpractices.dev/); this baseline does not claim a badge automatically.

## Before registering

Review the current [passing criteria](https://www.bestpractices.dev/en/criteria) and complete the project-specific items that a factory cannot determine:

- choose and add an appropriate open source `LICENSE`;
- document the supported platforms, build commands, tests, and release process;
- configure the profile-specific CI workflow and keep it passing;
- review the security, dependency, and code-scanning settings on GitHub;
- document project maintainers, release ownership, and continuity arrangements;
- ensure release notes identify known runtime vulnerabilities and relevant mitigations.

The factory supplies the reusable controls and evidence surfaces for these areas, including `SECURITY.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, repository issue forms, pull request requirements, dependency automation, CI, baseline validation, and private vulnerability reporting guidance.

## Register and record the result

1. Register the repository at [bestpractices.dev](https://www.bestpractices.dev/).
2. Work through the criteria using repository evidence; mark criteria as met only when the project actually satisfies them.
3. Add the generated badge and project link to `README.md` once the assessment is complete.
4. Revisit the assessment when the repository, release process, or criteria change.

Do not copy a badge URL from another project or describe the project as certified before the assessment is complete.
